Data Centre Server Troubleshooting: Hardware & OS

A first-response guide to power, POST, RAID, storage, hardware health, resource pressure and out-of-band management alerts.

BY BIBEK CHAUDHARY　·　PRACTICAL TROUBLESHOOTING GUIDE

Scope and safety

This is a first-response learning guide. Follow the organisation's approved runbooks, access controls and change process. Use read-only diagnostics first. Do not alter production configuration, reload equipment, move live cabling or interrupt services without explicit authorisation and an approved change.

1. Confirm service impact before intervention

  • Determine whether the host is production, development or a cluster member, and identify dependent services through approved documentation.
  • Check monitoring, incident records and maintenance schedules before touching hardware.
  • Confirm ownership, support contract and escalation path.

2. Power, POST and console symptoms

  • Check rack PDU status, power supplies, LEDs and documented power redundancy without disturbing live feeds.
  • Capture POST messages, diagnostic codes and hardware event logs.
  • Use out-of-band management such as HPE iLO or Dell iDRAC to review health, inventory and alerts where authorised.
  • Do not power-cycle or reseat components in a live production server without approval.

3. Storage and RAID health

  • Review controller status, physical disk state, virtual disk state, rebuild progress and predictive failure alerts.
  • Distinguish a degraded array from a failed logical volume; record the controller's exact alert and timestamp.
  • Check backup status and recovery implications before any storage intervention.
  • Never remove a disk based only on slot lights or assumptions; follow the controller and vendor procedure.

4. OS and resource pressure

  • Check CPU, memory, disk capacity, I/O latency and key service health using approved monitoring.
  • Correlate performance changes with deployments, scheduled jobs, patching and application events.
  • For virtual machines, involve the virtualisation team when host contention, datastore capacity or cluster events may contribute.

5. Network and environmental checks

Validate link state, redundant NIC paths, expected VLAN and switch-port health with the network team. Review temperature, fan, PSU and environmental alerts. Do not bypass thermal, power or security protections.

Escalation package

Provide server asset name, model, serial reference through approved channels, OS or hypervisor, service impact, event logs, management-controller alerts, RAID state, recent changes and backup/recovery status. Keep credentials and management addresses private.

Good incident records capture scope, impact, timestamps, device identifiers permitted by policy, evidence, checks performed, recent changes and the next owner. Remove passwords, secrets, public IPs and sensitive topology details from public notes.
