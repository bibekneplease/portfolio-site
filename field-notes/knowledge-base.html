PRACTICAL INFRASTRUCTURE REFERENCE / 01

Infrastructure troubleshooting
knowledge base.

A structured reference for enterprise support and infrastructure operations: understand the service path, narrow the fault domain, collect safe evidence and escalate with a useful handover.

BY BIBEK CHAUDHARY　·　NETWORKS / ENDPOINTS / DATA CENTRES

01 / UNDERSTAND THE PATH

Enterprise connectivity at a glance

Use this simplified logical view to identify where a user or service path may be failing. Actual enterprise designs vary; validate every hop against approved site documentation.

Endpoint & access

Power, cable, Wi-Fi association, IP configuration, VLAN, DHCP and local device health.

Network path

Switch port state, routing, DNS, firewall policy, WAN circuit, VPN and provider reachability.

Service layer

Application availability, authentication, dependencies, server health and monitoring events.

02 / DECISION TREE

Network connectivity: where do you look next?

A first-response decision path for a user reporting that an application or network resource is unreachable.

STARTConfirm impact and scopeOne endpoint, one VLAN, one site, multiple sites or one application? Record start time and business impact.
↓
Does the endpoint have expected IP, gateway and DNS?Check approved endpoint configuration; compare with a known-good device on the same network.
No / unexpected addressInvestigate link or Wi-Fi, DHCP lease/scope, VLAN assignment and local adapter. Escalate switch or DHCP changes.
Yes / expected addressContinue with gateway and destination tests. A failed ping alone is not conclusive because ICMP may be filtered.
↓
Can the approved gateway and a known-good internal destination be reached?Use permitted tests and compare results from another endpoint or segment.
Gateway failsCheck local link, access port, VLAN and gateway availability with the network team.
Gateway worksCheck DNS resolution, route/path, firewall policy and destination service health.
↓
Is the issue isolated to one hostname or application?Compare name resolution, service status and permitted destination ports; collect timestamps and evidence.
Document, escalate and monitorAttach sanitised outputs, scope, tests, recent changes and next owner. Do not make unapproved configuration changes.

03 / DECISION TREE

Server or data-centre alert

A safe triage sequence for hardware-health, storage, power or performance alerts.

STARTConfirm host identity, service impact and change windowCheck monitoring, ownership, maintenance records and approved runbook before touching equipment.
↓
Is there a critical power, thermal, fan or hardware alert?Review BMC / vendor management health and facility monitoring where authorised.
Yes / safety or hardware riskDo not power-cycle or reseat components. Preserve alert details and escalate to data-centre / hardware support immediately.
No critical hardware alertContinue with storage, OS, network and application health checks.
↓
Is storage degraded or capacity / I/O under pressure?Review controller, disk, volume, backup and monitoring state. Never remove a disk based only on an LED.
Degraded / failure suspectedCapture controller state and rebuild status; stop before intervention and follow vendor / change procedure.
Storage healthyCorrelate CPU, memory, services, virtualisation, network and recent deployments.
Record evidence and hand overInclude asset, service impact, timestamps, alerts, recent changes, backup status and escalation owner.

04 / SAFE COMMAND REFERENCE

Read-only diagnostics

Examples for authorised troubleshooting sessions. Commands can expose internal addresses, hostnames or topology; redact output before sharing externally.

Windows endpoint

ipconfig /allIP, gateway, DNS, DHCP
ping <approved-host>Basic reachability test
tracert <approved-host>Path visibility
nslookup <hostname>DNS query result
Get-NetAdapterAdapter state (PowerShell)

Cisco IOS / IOS-XE

show interfaces statusPort state and VLAN
show interfaces counters errorsError counters
show ip interface briefInterface summary
show ip routeRouting table
show loggingRecent system events

Linux server

ip addrAddress/interface state
ip routeRouting table
df -hFilesystem capacity
free -hMemory summary
uptimeLoad and uptime

General service checks

Get-ServiceWindows service state
systemctl status <unit>Linux service state
ss -tulnListening sockets
journalctl -p warning -n 50Recent warnings
Safety boundary

These examples are intended for observation, not remediation. Do not run configuration, reset, clear-counter, reload, shutdown, disk repair, firewall, routing or service-restart commands on production systems unless explicitly authorised through the organisation's change process. Use least-privilege access and approved runbooks.
